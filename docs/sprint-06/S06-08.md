# S06-08 — Entrées physiques → DSP → casque et enceintes

Quatre Nodes concrets forment Source → Gain 0,5 → Output deux paires → writer
partiel. La source au layout d'entrée vide choisit les voies physiques 2 et 6.
Les six arêtes portent uniquement des canaux logiques du pool. Le Node Output
écrit les paires physiques 0/1 (casque) et 2/3 (enceintes) depuis ses inputs
logiques. Un successeur lit ses sorties logiques et réécrit seulement la voie 0
aux offsets pairs avec un gain 2. La source est aussi marquée output mais choisit
de ne pas écrire : rôles et routage restent indépendants. Les voies 4/5 restent
silencieuses. Aucune référence matérielle n'est ajoutée à la production.

Les samples attendus sont calculés depuis les vraies entrées du backend : gain
0,5 sur les quatre voies utilisées, puis dernier write effectif sur la voie 0
paire. Deux backends alternent toutes leurs adresses sur frames 0/1/2/7/128.
Les tests comparent valeurs exactes, entrées inchangées, gardes, samples hors
frames, stabilité des descripteurs internes et absence de vues backend retenues.

Un second cas refuse maxFrames+1, voies manquantes, capacités sample trop courtes
et input nul. Il vérifie silence borné, absence de process et diagnostics, puis
reprend sur le même plan après un callback zéro frame à pointeurs nuls.
Le montage complet et un refus sont mesurés sans new/delete ni mutex dans le
binaire RT. La suite complète est aussi exécutée sous ASan/UBSan et LeakSanitizer.

Résultat final : **283/283 tests passent en Debug et sous ASan/UBSan**, avec
`ASAN_OPTIONS=detect_leaks=1:halt_on_error=1` et
`UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1`. Doxygen : aucun avertissement ;
`git diff --check` propre. Les tests instrumentés ne désactivent aucune assertion
et le contrôle des fuites s'exécute hors de la restriction ptrace du bac à sable.
