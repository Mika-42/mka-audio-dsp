# S06-04 — Outputs physiques directs, séparés des sorties logiques

Le plan utilise déjà les rôles de sortie capturés sur contrôle et rebind le
tableau de float* du callback pour chaque Node marqué output. Depuis S06-01,
chaque span possède exactement outputChannels éléments. Les autres Nodes ont
un span vide. Les ChannelID physiques restent zéro et aucune arête matérielle
n'est créée. Les Nodes choisissent leurs voies dans leur propre process.

Le nouveau writer concret de test produit des valeurs différentes dans le pool
et sur le matériel. Les cas 0/1/2/6 voies vérifient un source+output avec
successeur : celui-ci lit toujours la production logique, indépendamment des
écritures physiques. Un Node non marqué ne peut pas écrire sur le backend.
Les tests vérifient directement adresses, types, absence d'alias et changement
de backend ; aucun pointeur callback n'est conservé dans l'état du Node.

Un second cas sélectionne librement la sixième voie avec un layout logique vide,
puis retire le marqueur sur le graphe. L'ancien plan garde son routage, le
nouveau perd backendOutputs, sans ajout/suppression de connexion.
