# S03-01 — Cycles avant connect

La recherche de chemin construit une adjacence temporaire puis parcourt les
successeurs de la destination. Atteindre la source refuse la candidate par
CycleDetected ; une auto-arête est détectée sans parcours. La priorité des
erreurs S02-03 (ports/direction/existence/doublon/occupation/cycle) est conservée.

Le DFS est itératif : chaque Node découvert est empilé une fois. Toutes les
arêtes In/Aux et hors Config participent, avec arêtes parallèles admises. Le
coût moyen est O(V+E) avec hash entier et stockage temporaire O(V+E), au lieu du
scan de toutes les arêtes pour chaque Node. Aucune pile récursive ou capacité
fixe non vérifiée. Les échecs de ressources sont capturés par connect.

Le contrôle possède les temporaires et les détruit avant retour ; le graphe,
les Node, marqueurs et plans ne sont jamais mutés avant insertion finale.
Aucun parcours, verrou, allocation ou destruction supplémentaire en callback.
Les vues externes du graphe restent empruntées et sérialisées avec ses éditions.

Validation : **169/169 tests passent** en C++26 Clang19/libc++19 et ASan/UBSan
avec détection des fuites. Cinq tests supplémentaires couvrent cycles 1/2/4,
diamant, fan-out, arêtes parallèles, Aux/hors Config, chaîne de 1024 Nodes avec
trous d’ID et oracle Floyd-Warshall indépendant sur 96 candidats. Les tests
d’injection de chaque allocation de connect et les fenêtres RT restent verts.
