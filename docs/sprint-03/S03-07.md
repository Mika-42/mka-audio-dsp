# S03-07 — Erreurs structurées

ErrorCode est une enum class uint16 à 14 catégories canoniques : InvalidParameter,
NodeNotFound, InvalidPort, InvalidDirection, ConnectionExists, InputOccupied,
CycleDetected, NodeInUse, CapacityExceeded, ArithmeticOverflow,
MemoryBudgetExceeded, PrepareFailed, LatencyOverflow et PlanBusy.

Error contient code, NodeID node et ChannelID channel, uniquement des valeurs
numériques sans message, pointeur ou ownership. Les champs non pertinents sont
zéro. GraphError/CompileError/PrepareError désignent ce même type ; Result est
expected<void,Error>. La construction constexpr/noexcept et la copie triviale
n’allouent pas. L’égalité Error compare les trois champs, l’égalité avec
ErrorCode compare la catégorie. Un message optionnel se produit hors RT.

Les anciens noms ErrorType::Code/GraphError::Code restent des constantes de
catégorie pour faciliter la migration ; ErrorType désigne désormais Error.
Les anciennes catégories fines sont regroupées dans les 14 catégories canoniques.
L’ancien ABI enum et ses numéros ne sont pas conservés : recompiler les clients
et lire error().code. Un constructeur implicite depuis ErrorCode facilite les
anciens retours unexpected(code) sans créer de représentation incompatible.

Les identifiants de base sont séparés dans identifiers et réexportés par types,
afin que Error utilise les vrais alias NodeID/ChannelID sans cycle d’import.
Les APIs et valeurs des identifiants ne changent pas.

Les statuts publics du DAG, du tri et de la préparation capturent bad_alloc et
les erreurs de capacité, puis retournent un Error stable sans mutation partielle.
Les erreurs de connexion donnent le canal fautif, ou la destination pour
doublon/occupation/cycle ; les erreurs par Node donnent son identité. Une valeur
historique non représentable n’est jamais tronquée dans le contexte. Les
ressources globales sans identité pertinente gardent les champs zéro.

Les constructeurs/copies propriétaires C++ continuent d’être des opérations de
contrôle allouantes selon leurs contrats précédents ; les frontières à statut
capturent leurs échecs. Aucun changement de traitement ou message dans exec/
process, aucun pool/publicateur fictif pour les codes destinés aux sprints
suivants. La PR dépend de S03-06.

Validation : **195/195 tests passent** en C++26 et ASan/UBSan avec détection
des fuites. Sept nouveaux tests vérifient les 14 catégories, largeur, alias,
constexpr, égalités et conservation complète des contextes sur DAG/préparation/
buffers. Un test additionnel injecte chaque échec d’allocation de compilation
backend, conserve le plan déjà préparé et réussit une nouvelle tentative. Les
oracles exhaustifs, 20 000 mutations et fenêtres RT sans allocation restent
verts après migration des comparaisons de catégories vers .code.
Revue indépendante sans défaut bloquant ; diff --check passe. Logs hors dépôt
s03-sequence-native/sanitized, préfixe S03-07.
