# S04-06 — Silence des sorties logiques non produites

Chaque opération Node efface ses seules sorties logiques sur [0,frames), juste
avant Node::process. Le nettoyage global de tous les slots au début du callback
est supprimé. Un producteur qui n’écrit rien rend du silence ; s’il écrit une
moitié ou des samples alternés, les trous restent zéro, même après un bloc plein
de sentinelles. Les slots sont ceux compilés pour cette opération, sans lookup.

Aucune entrée In/Aux, donnée d’un prédécesseur encore lue par fan-out, ni slot
silence n’est effacé. Le pool minimal affecte toujours des sorties distinctes ;
le nettoyage à l’opération reste valable lorsque le recyclage inter-opérations
sera ajouté au sprint 5 avec son analyse de dernière utilisation. Ici les tests
réemploient les mêmes slots stables entre callbacks, sans introduire de recyclage
anticipé. Les contextes empruntent les buffers du plan et les entrées restent
const float*. Aucun Node ne reçoit le droit d’écrire le buffer d’un prédécesseur.

Les sorties physiques sont effacées séparément au début du callback. Les
écritures physiques effectives suivent le LWW ; aucune sortie backend n’entre
dans le nettoyage logique par Node. frames=0 ne touche aucun sample. Une forme
de callback invalide est refusée avant tout nettoyage logique et conserve les
slots internes du plan. Les boucles RT sont bornées et sans allocation, mutex,
attente ni exception. Préparer et retirer les ressources uniquement sur contrôle
après quiescence ; le DAG conserve les Nodes empruntés.

Validation : 230/230 tests passent en C++26 natif et ASan/UBSan avec détection
des fuites. Deux nouveaux tests couvrent slots multi-output pleins de sentinelles
puis partiellement/non écrits, frames 0/1/128, fan-out, chaîne non source et
préservation des données de prédécesseurs encore vivantes. Un test RT de writer
partiel vérifie les trous logiques et physiques sans heap ni mutex. Doxygen
sans avertissement ; git diff --check propre.
