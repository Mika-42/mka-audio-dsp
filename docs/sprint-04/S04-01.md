# S04-01 — Tâche de traitement concrète

ExecutionTask est exactement l’agrégat {Node* node; ProcessContext context;}.
Il n’hérite de rien et n’alloue ni ne possède le Node. Les métadonnées du sprint
3 restent accessibles via TaskInfo et taskInfos() : identité, position et rôles.
Les clients qui lisaient ces métadonnées via executionTasks() migrent vers
taskInfos(). executionTasks() expose maintenant les vraies opérations exécutées.
Le budget structurel inclut aussi ces contextes, avec calcul d’overflow conservé.

Le plan prépare les descripteurs et buffers avant de lier les spans de contexte.
exec appelle exactement task.node->process(task.context) dans l’ordre compilé,
une fois pour chaque bloc valide, y compris frames=0 sans accès aux samples.
Le helper historique withProcessContext conserve son contrat zéro-frame no-op ;
le plan exécute directement ses contextes préparés. Les vues sources et sorties
backend sont liées au callback courant puis vidées ; aucun pointeur externe
n’est conservé entre deux appels. Les entrées internes et Aux restent en lecture,
les sorties logiques en écriture et distinctes du backend.

Copier un plan recopie les buffers/descripteurs et répare ses contextes sur
contrôle. Déplacer un plan transfère les allocations stables et vide l’ancienne
génération ; aucune relocation n’a lieu sur le thread audio. Le DAG doit survivre
à ses plans et aux vues empruntées. Les suppressions souhaitées reportent la
destruction des Nodes jusqu’à la retraite de toutes les générations concernées.
Préparation, copie, déplacement, remplacement et destruction exigent la quiescence.
