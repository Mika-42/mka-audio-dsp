# S04-03 — Entrées silencieuses

Le pool possède un slot mono de maxFrames floats initialisés à zéro sur contrôle.
Son accès dédié silenceBuffer ne retourne que const float*. Les accès ordinaires
aux slots excluent zéro ; aucune sortie logique ne reçoit ce slot, qui n’est
jamais effacé, écrit ou recyclé par les callbacks. Plusieurs In/Aux peuvent lire
la même adresse. Le contrat interdit aux Nodes de contourner const par un cast.

Chaque entrée déclarée non reliée ou dont la sortie source n’est pas matérialisée
lit ce silence. Les arêtes hors Config restent dans le DAG et contribuent aux
dépendances sans créer de descripteurs supplémentaires. Une source topologique
reçoit toutes les entrées backend réelles ; ses Aux non reliés restent silencieux.
Les layouts vides sont permis. À zéro frame, les tâches s’exécutent sans accès
aux samples ; à maxFrames=0 aucun sample n’est alloué ou consommé.

Les descripteurs et buffers sont empruntés pour la durée du plan, propriété de
celui-ci. Le graphe conserve ses Nodes jusqu’à la retraite des emprunts. Le plan
est préparé et ses liens fixés sur contrôle ; seul le callback actif rebind les
vues externes, sans allocation, mutex, attente ni exception.

Validation : 216/216 tests passent en C++26 natif et ASan/UBSan avec détection
des fuites. Trois nouveaux tests couvrent fan-out de silence In/Aux, absence
d’alias de sortie, deux callbacks et plus, zéro source, layouts vides ou
incomplets, frames 0/1/128/max et capacité nulle. Doxygen sans avertissement ;
git diff --check propre.
