# S04-07 — Source → Gain → Output sans matériel

Un backend simulé possède des tableaux fixes avec canaris, deux entrées const
et deux sorties physiques, plus une troisième voie optionnelle non écrite.
Ses tableaux de pointeurs et buffers vivent durant les callbacks ; le fixture
n’est ni copiable ni déplaçable pour préserver ses adresses internes. Aucun
périphérique, service ou driver local n’est requis.

Trois vrais Nodes compilés forment Source → Gain → Output. La source topologique
lit les deux entrées physiques courantes et produit deux sorties logiques ; le
Gain multiplie chaque sample par 0,5 ; seul le Node Output est marqué sortie et
copie ses entrées logiques vers backendOutputs. Les quatre connexions du DAG
restent internes, sans numéro matériel ni Node spécial de routage. Les Nodes
ne retiennent aucun pointeur de contexte ou backend.

Le graphe est compilé une fois, puis exécuté avec frames 0/1/128/256 et deux
backends ayant des adresses et signaux différents. Les comparaisons indépendantes
calculent input[i]*0,5 sample par sample sur chaque voie. Les entrées ne sont
jamais modifiées, les samples hors frames restent intacts et une voie physique
présente mais non écrite reste zéro. Les adresses internes du plan sont stables.

Un bloc de 257 frames, avec buffers explicitement limités à 256, ne traite aucun
Node, rend un silence borné et conserve les canaris. Un callback de zéro frame
à pointeurs nuls s’exécute sans accès sample ; le callback valide suivant reprend
le traitement. Le diagnostic est relevé sur contrôle. Préparation et destruction
sont hors RT après quiescence ; le graphe propriétaire survit à son plan.

Le même fixture est partagé avec le binaire d’instrumentation RT : 64 blocs
alternent tailles et buffers, puis un refus de capacité vérifie le fail-safe,
sans allocation/libération ni prise de mutex. Aucun changement de production
n’est nécessaire pour cette recette d’intégration.

Validation finale : **233/233 tests passent** en C++26 natif et ASan/UBSan avec
détection des fuites ; **215/215 sous ThreadSanitizer**, dont le relevé concurrent
de diagnostic. Les 18 tests du binaire d’interception new/delete et mutex passent
en natif et ASan ; ses remplacements globaux d’allocation sont incompatibles
avec les intercepteurs TSan. Aucun test du binaire principal n’est exclu.
Deux nouveaux tests d’intégration et une fenêtre RT partagent le même montage
stéréo, avec comparaisons exactes, canaris et zéro heap/mutex. Doxygen 1.13.2
génère tous les modules sans avertissement ; git diff --check propre.

Logs hors dépôt : s04-sequence-native, sanitized et threadsanitized, préfixe
S04-07 ; documentation générée dans s04-doc. Les sept fiches ont chacune leur
branche, commit et PR vers main, en filiation pour conserver leurs prérequis.
