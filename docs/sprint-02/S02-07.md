# Sprint 2, fiche 7 — S02-07 : marquage des sorties

**Implémentée, en attente de validation.** [Trello #15](https://trello.com/c/8MYAy6PM).
PR vers main dépendante de S02-06 ; fusion manuelle dans l’ordre des fiches.

`markAsOutput(NodeID)` et `unmarkAsOutput(NodeID)` retournent expected<void,
GraphError>. Un Node absent produit NodeNotFound, sans mutation. Les répétitions
sont idempotentes ; le stockage privé outputsNodes_ est unique et trié par
NodeID croissant. L’échec d’allocation lors du marquage est retourné comme
AllocationFailed sans modifier la collection ; unmark n’alloue pas. Remove
efface le marqueur avec le Node du graphe souhaité.

`outputNodes() const noexcept` expose un span<const NodeID> de consultation sur
contrôle. Les valeurs appartiennent au DAG ; aucune propriété de Node/buffer
n’est transférée. Toute édition peut invalider la vue, à copier pour conserver
un instantané. Sérialiser les éditions et lectures de cet état souhaité.

Un marqueur ne réserve aucune voie et ne crée aucune arête ou identité hardware.
La source topologique et la sortie sont indépendantes ; des successeurs sont
autorisés. Le Node marqué reçoit toutes les sorties physiques du callback dans
backendOutputs, distinctes de ses outputs logiques possédés par le plan.
Chaque Node choisit ses écritures. Le dernier write effectif par sample gagne
dans l’ordre topologique stable, indépendamment de l’ordre des marquages.

Les rôles d’un plan déjà préparé restent figés après mark/unmark/remove ; seul
un nouveau plan reflète le nouvel état. Le backend reste propriétaire des
samples prêtés pour le callback ; les descripteurs sont rebindés puis nettoyés
par le plan. Aucun Node ne retient de pointeur matériel. Aucune allocation,
libération, attente, I/O ou modification de propriété n’est ajoutée au callback.
