# Sprint 2, fiche 6 — S02-06 : suppression et retrait différé

**Implémentée, en attente de validation.** [Trello #14](https://trello.com/c/0ZpwaMB7).
PR vers main dépendante de S02-05 ; fusion manuelle après les fiches précédentes.

```cpp
std::expected<void, GraphError> DAG::remove(NodeID id);
```

Une identité absente produit NodeNotFound sans mutation. Un retrait réussi
efface toutes les arêtes incidentes, le marquage output et l’entrée dans la
recherche des Node souhaités. Les autres arêtes et marqueurs sont conservés.
L’API prend maintenant exactement NodeID uint32 : valider toute valeur externe
plus large avant conversion. Les identités ne sont jamais réutilisées.

Le stockage de retrait introduit en S02-01 est conservé : avant d’effacer le
graphe souhaité, sécuriser le transfert du unique_ptr vers la collection de
retrait si un plan emprunte le Node. Une allocation/capacité en échec laisse
Node, arêtes et marqueurs intacts. Sans emprunt, la destruction polymorphe est
immédiate sur contrôle. Avec emprunts, l’adresse reste stable et les anciens
plans gardent leurs tâches et bindings.

Chaque propriétaire de plan, qu’il soit Ready, Pending, Active ou Retired,
retient ses jetons jusqu’à sa retraite sur contrôle. Une seule génération ou
un seul ACK ne suffit pas. `collectRetiredNodes()` détruit uniquement après le
dernier emprunt, sur contrôle, sans allocation ni destruction dans exec/process.
Le propriétaire doit conserver le plan actif jusqu’à installation de son
remplacement et acquittement de son dernier callback. Libérer les emprunts de
toutes les générations et les usages bruts externes avant la collecte ; le DAG
doit survivre à tous les plans. Le callback ne modifie aucun jeton.

Les tests représentent ces rôles par de vrais propriétaires ExecutionPlan côté
contrôle et acquittent le callback du worker avant sa retraite. Ils ne livrent
pas le protocole de publication A/B prévu au sprint 7. Un échec de compilation
du remplacement conserve le propriétaire A actif et donc son Node. Les
barrières d’un test sont dans le harness, jamais dans Node::process.

Validation : **156/156 tests passent** en C++26 et sous ASan/UBSan avec détection
des fuites ; cinq tests dédiés couvrent les retraits isolés/incidents, les
marqueurs, le rollback, l’échec de B, plusieurs générations et B installé après
ACK du callback. Aucun diagnostic et destruction exactement une fois sur contrôle.
La revue indépendante n’a relevé aucun défaut bloquant.

**150/150 tests fonctionnels passent sous ThreadSanitizer**, dont le test
contrôle/callback avec ACK. Compiler la cible mka-audio-dsp-tests puis utiliser
CTest `-R '^dsp\.' -E '^dsp\.rt\.'`. Le binaire séparé d’interception new/delete
est incompatible à l’édition de liens avec les intercepteurs TSan ; ses six
tests sont exécutés en natif et ASan/UBSan, sans désactiver leurs compteurs.
