## API et migration des appelants

```cpp
[[nodiscard]] std::expected<void, GraphError>
DAG::connect(ChannelID destination, ChannelID source);
```

Le premier argument consomme le signal (In ou Aux), le second le produit (Out).
L’insertion reste `Connection{.from = source, .to = destination}`. Exemple :

```cpp
const auto destination = consumer.channel(PortType::Aux, 65535);
const auto source = producer.channel(PortType::Out, 42);
auto connected = graph.connect(destination, source); // traiter l’erreur sur contrôle
```

Les appelants utilisant l’ancienne convention doivent **inverser leurs deux
arguments** et recompiler. La signature comporte deux entiers identiques : le
compilateur ne détecte pas une ancienne convention. Le contrôle des rôles la
rejette par `InvalidDirection` sans mutation. Les deux ordres ne sont jamais
acceptés simultanément. La surcharge historique prenant deux Channel suit la
même convention destination/source et garde ses vérifications de champs larges.
Les appels `disconnect` existants ne changent pas ; leur harmonisation précise
par canaux appartient à S02-05.

## Contrôles et erreurs

Le décodage conserve les 32 bits de NodeID, les 16 bits du port et les 16 bits
de l’indice, sans normaliser un port inconnu. L’ordre de validation est fixé :

| Priorité | Erreur | Condition |
|---|---|---|
| 1 | InvalidPort | Au moins un code de port est hors enum In/Out/Aux |
| 2 | InvalidDirection | Source définie autre que Out, ou destination définie autre que In/Aux |
| 3 | NodeNotFound | Au moins une identité de Node est absente, y compris zéro |
| 4 | ConnectionExists | Le couple exact source/destination est déjà stocké |
| 5 | InputOccupied | La destination exacte possède déjà un autre producteur |
| 6 | CycleDetected | Auto-arête ou chemin destination → source déjà présent |

Ces six erreurs possèdent des codes distincts. `ConnectionExists` conserve la
valeur numérique de l’ancien `ConnexionAlreadyExists`, et `InputOccupied` celle
de `ChannelAlreadyConnected`. Les anciennes orthographes restent des alias ;
aucune autre valeur d’énumération n’est décalée. Un port hors enum possède
maintenant son erreur propre au lieu d’être assimilé à une mauvaise direction.

Un doublon est signalé avant l’occupation du même canal. L’occupation est
signalée avant une éventuelle fermeture de cycle ; les refus simples ne
lancent ainsi aucun parcours allouant. Le parcours de cycle inclut toutes les
arêtes In/Aux, quel que soit le layout. Une auto-arête avec destination libre
est refusée immédiatement par le test de chemin sur le même Node.

Une sortie peut alimenter plusieurs destinations ; In et Aux de même indice
restent deux entrées distinctes. Un indice absent de Config est structurellement
admis, y compris 65535 et les layouts vides. Aucun routage matériel ne passe
par ces connexions : un marqueur output n’est pas une arête.

L’adaptateur Channel teste les ports, la direction, l’existence des Node sur
leurs valeurs larges, puis les indices via `toChannelIndex` avant encodage.
Les identités larges ne peuvent pas se tronquer en une identité existante.
Un indice supérieur à 65535 produit `InvalidChannelIndex` et aucune insertion.

## Transaction, propriété et threads

L’opération s’exécute uniquement sur contrôle, avec sérialisation externe des
éditions du DAG. Elle valide tout avant l’unique insertion finale par valeur.
Un refus ne modifie ni les arêtes, ni les marqueurs, ni les Node ou leur état
DSP. `bad_alloc` devient `AllocationFailed` ; un dépassement de capacité de
stockage devient `ConnectionCapacityExceeded`. La collection d’arêtes reste
inchangée si le parcours ou l’insertion échoue.

DAG possède les Connection et les Node. Les valeurs d’arêtes ne possèdent aucun
Node ni buffer ; les tableaux du plan sont préparés sur contrôle. Le span
`connections()` reste une vue en lecture seule invalidable par les éditions,
à copier pour garder un instantané indépendant. Aucun Node ou pointeur audio
n’est transféré lors d’un `connect`.

Un succès modifie seulement le graphe souhaité. Un plan préparé auparavant
conserve ses tâches, rôles, liaisons, buffers et jetons d’emprunt. Une nouvelle
compilation est nécessaire pour refléter la nouvelle connexion. Ni le callback
ni `process` ne valide ou n’édite le DAG ; aucun verrou, attente, exception ou
allocation audio n’est ajouté. Les règles de quiescence et de propriétaire
survivant aux plans restent celles des fiches précédentes.

L’occupation est contrôlée ici parce que S02-03 l’exige. Cela ne valide pas
S02-04 et ses scénarios propres. Les API disconnect, remove, output et les
protocoles de publication ne sont pas refondus par cette fiche.

## Validation exécutée

Compilation C++26 réussie avec Clang 19.1.7/libc++19, CMake 4.3.4 et Ninja.
**142/142 tests CTest passent**, sans test ignoré ou désactivé : 136 tests
existants adaptés à la convention et aux erreurs, plus six nouveaux tests de
contrat et de transaction. Les assertions statiques vérifient le retour
`expected<void, GraphError>` et les six erreurs sémantiques distinctes.

Les tests couvrent la table des neuf directions, In/Aux, les arguments inversés,
les identités absentes ou à bits hauts, les ports malformés sans normalisation,
les indices 65535/hors Config, le fan-out, les doublons, l’occupation, les
auto-arêtes et les cycles indirects contenant des Aux. Les cas combinant des
erreurs vérifient la priorité documentée. L’adaptateur historique utilise lui
aussi la destination en premier et refuse les champs non représentables.

Pour chacun des six refus sémantiques, un test garde un instantané des arêtes,
adresses et tâches, exécute l’ancien plan puis une nouvelle compilation du même
graphe et vérifie le même résultat audio (`8`) et les mêmes rôles de sortie.
Les tests d’injection d’échecs d’allocation et les fenêtres RT de 64 callbacks
restent verts, avec zéro allocation/libération C++ dans le traitement mesuré.

Une seconde compilation passe aussi les **142/142 tests sous ASan/UBSan**, avec
détection des fuites activée et sans diagnostic. Options :
`-fsanitize=address,undefined -fno-omit-frame-pointer -fno-sanitize-recover=all`,
`ASAN_OPTIONS=detect_leaks=1:halt_on_error=1`, `UBSAN_OPTIONS=halt_on_error=1`.
LeakSanitizer a été exécuté hors de la restriction ptrace du sandbox, avec le
runtime LLVM local `libclang-rt-19-dev` ; aucune instrumentation n’est désactivée.

La revue indépendante de la production et des migrations existantes n’a trouvé
aucun défaut bloquant. Les nouveaux tests ont été relus et exécutés avec les
deux configurations. `git diff --check` passe.
