# Sprint 2, fiche 5 — S02-05 : déconnexion exacte et idempotente

**Implémentée, en attente de validation.** [Trello #13](https://trello.com/c/YyfwJ1r3).
PR dépendante de S02-04, vers main ; fusion manuelle dans l’ordre.

```cpp
std::expected<bool, GraphError> DAG::disconnect(ChannelID destination, ChannelID source);
```

`true` signifie que le couple exact `Connection{source,destination}` a été
retiré ; `false` signifie déjà absent, sans erreur. Tester d’abord le résultat
expected, puis sa valeur booléenne. Un appel valide sur arête absente ne modifie
aucune autre liaison entre les mêmes Node. In/Aux, indices et fan-out restent
indépendants ; aucun layout Config n’est consulté.

Conformément à cette fiche, un code de port malformé ou une direction interdite
retourne `InvalidDirection` (connect distingue InvalidPort). Puis un Node absent
retourne `NodeNotFound`, même si l’arête n’existe pas. Ces erreurs précèdent la
recherche et laissent le graphe inchangé.

L’ancienne API par deux NodeID avait la même signature entière mais un autre
sens : les appelants doivent désormais passer les deux ChannelID exacts,
destination d’abord. Les appels du dépôt sont migrés ; les anciens codes
ConnexionNotFound restent dans l’énumération pour compatibilité mais une arête
déjà absente n’est plus une erreur pour disconnect.

L’opération est réservée au contrôle, avec sérialisation externe. Le DAG possède
les valeurs d’arêtes et les Node ; cette opération ne possède ni ne détruit de
Node ou buffer, n’alloue pas et ne prend pas de verrou. Elle invalide les vues
empruntées de la collection comme toute édition. Un plan déjà préparé garde
ses bindings et son routage ; compiler un nouveau plan applique la déconnexion.
La suppression libère l’occupation de la destination dans le graphe souhaité.

Validation : **151/151 tests passent** en C++26 Debug Clang19/libc++19 et sous
ASan/UBSan avec détection des fuites, sans diagnostic ni test désactivé. Quatre
nouveaux tests couvrent couple exact, Aux/indices indépendants, true puis false,
refus avec rollback et ancien plan inchangé (résultat 5, nouveau plan 4).
Les anciens appels ont été migrés avec vérification séparée de expected/bool.
