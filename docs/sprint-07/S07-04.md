# S07-04 — Retrait de l'ancien plan après ACK

retireAcknowledgedPlan acquiert l'ACK avant de toucher A. Le nouveau slot devient
le miroir actif contrôle, A passe conceptuellement Retired, ses ressources sont
libérées sur contrôle, puis il devient Free et le handshake revient Idle. Avant
ACK, l'API renvoie PlanBusy sans toucher au plan ni à ses références.

Les tests comptent la destruction d'un Node retiré, l'absence de destruction
avant ACK, le nettoyage unique et la conservation de l'adresse de l'emplacement.
Un Node partagé entre A et B reste vivant après le premier ACK : seul le retrait
de B après la génération suivante libère sa dernière référence de plan.

Le binaire d'interception constate zéro delete pendant swap/exec et des
libérations uniquement dans la fenêtre contrôle de retirement. Le DAG possède
toujours le Node jusqu'à collectRetiredNodes ; aucun destructeur Node n'est appelé
sur le thread audio. Le mécanisme de borrows existant couvre toutes les générations.
