## Interface publique

Le module `mka.audio.dsp.node` expose les types de configuration, de canal et
de contexte dont son interface a besoin :

```cpp
class Node {
public:
    explicit Node(NodeID id, const Config& config); // contrôle, peut allouer
    virtual ~Node() = default;
    virtual void process(const ProcessContext&) noexcept = 0;
    [[nodiscard]] virtual std::uint32_t latencySamples() const noexcept { return 0; }
    [[nodiscard]] NodeID id() const noexcept;
    [[nodiscard]] ChannelID channel(PortType, ChannelIndex) const noexcept;
    [[nodiscard]] const Config& config() const noexcept;
};
```

Node est abstraite et non final ; un effet dérivé peut être final. Le
destructeur est public et virtuel, `process` pure virtuelle et `latencySamples`
virtuelle non pure, avec une valeur par défaut exactement zéro. Les trois
accesseurs ordinaires sont const/noexcept, **non virtuels** et sans allocation.
Aucun `prepare()` universel n’est ajouté.

`id_` est désormais un NodeID 32 bits et `id()` renvoie une valeur, sans exposer
de référence interne. `channel()` retourne le ChannelID numérique de S01-03,
indépendamment du layout ou d’un backend. Sa précondition est un PortType
valide ; contrôler les ports décodés et les indices larges avant appel, avec
`isValidPort` et `toChannelIndex`. Les conversions ne doivent pas tronquer des
données externes avant d’arriver dans cette API typée.

L’identité doit être attribuée en contrôle, non nulle et cohérente avec son
propriétaire. Le constructeur copie Config, avec la précondition habituelle
`validateConfig(config)` réussie. Il peut allouer, y compris pour son jeton
d’emprunt, et n’est pas noexcept. `Node::Config` reste l’alias du type public.

Les copies et déplacements de Node sont supprimés : l’identité, l’adresse et
le snapshot de configuration ne peuvent être clonés ou déplacés implicitement
pendant qu’un plan les utilise. Les Config restent copiables indépendamment.

## Contrat de traitement et de latence

`process(const ProcessContext&) noexcept` consomme les vues synchroniquement.
Les implémentations ne doivent ni allouer/libérer de mémoire, ni verrouiller,
attendre, effectuer de logging/I/O ou propager d’exception. Elles ne conservent
pas les pointeurs matériels ou le contexte après le callback. La constance des
descripteurs et les droits sur les samples sont ceux de S01-04/S01-06.

La signature noexcept interdit de relâcher la spécification dans un override ;
elle ne prouve pas qu’un corps arbitraire de processeur est compatible RT.
Les restrictions restent un contrat de l’implémentation, vérifié sur les effets
de test par inspection et par mesure des opérations de tas C++.

`latencySamples()` décrit la latence intrinsèque en échantillons entiers. Elle
est lue en contrôle à partir d’un état cohérent, sans mutation concurrente d’un
état DSP partagé. Préparer un futur plan ne doit pas modifier l’état utilisé
par le plan actif ; la préparation faillible d’un effet reste hors RT avec un
résultat structuré et une coordination de génération adaptée. Aucun calcul
PDC ni protocole de publication n’est ajouté dans cette fiche.

## Propriété et destruction après les emprunts

Le DAG conserve ses `unique_ptr<Node>` : il reste propriétaire. Les tâches de
plan conservent des `Node*` **empruntés**. Afin d’éviter leur invalidation par
une suppression, chaque Node possède un état d’emprunt opaque et le plan
retient des jetons qui partagent cet état, jamais la propriété du Node.
Le DAG est non copiable et non déplaçable : remplacer son état par affectation
ou transférer son ownership ne peut pas contourner le contrôle de suppression.

À la livraison de S01-07, lorsqu’un plan compilé référence un Node, `DAG::remove` retourne
`ErrorType::NodeInUse`, **sans supprimer le Node ni ses arêtes**. Le code est
ajouté en fin d’énumération pour préserver les valeurs existantes. Après le
dernier callback, retirer tous les plans qui empruntent ce Node sur le thread
de contrôle, puis réessayer la suppression. Le destructeur polymorphe est alors
appelé exactement une fois par le propriétaire.

[S02-01](../sprint-02/S02-01.md) remplace ensuite ce refus par un stockage
propriétaire de retrait différé : la recherche ne voit plus le Node retiré,
les anciens plans le conservent vivant et une collecte explicite sur contrôle
le détruit après le dernier emprunt. `NodeInUse` reste dans l’énumération pour
préserver les valeurs existantes.

La copie d’un plan retient les emprunts. Son déplacement les transfère et
laisse le plan source vide. Les affectations libèrent correctement les anciens
emprunts ; l’affectation par copie utilise copie-et-échange pour conserver un
état cohérent si une allocation échoue. Ces opérations ainsi que la destruction
des plans se font **en contrôle seulement**, après quiescence de leurs usages.
Aucun jeton n’est copié/libéré pendant `process` ou les accesseurs Node.

### Préconditions et limites de cette protection

- Le DAG (ou tout autre propriétaire explicite de Node) doit **survivre à tous
  les plans et emprunts**. Un jeton d’emprunt ne garde pas le Node vivant après
  destruction prématurée du propriétaire.
- Ne pas retirer un plan pendant qu’un callback l’utilise encore. La présence
  des jetons ne constitue pas un protocole d’acquittement entre threads.
- Les vues retournées par `tasks()`/`layer()` et leurs pointeurs ne doivent pas
  être conservés au-delà de la retraite ou modification du plan concerné.
- Dans la livraison S01-07, la suppression est refusée puis réessayée : aucune file automatique de
  destruction différée, édition à chaud ou publication A/B n’est livrée ici.
- Un destructeur public reste appelable par un propriétaire qui viole le
  contrat ; le type ne peut interdire universellement un delete mal placé en RT.

Les helpers d’emprunt sont isolés dans `detail` du module Node pour éviter des
forward declarations de classes appartenant à d’autres modules C++ nommés.
Ils ne représentent pas une API métier ni un changement de propriété des Nodes.

## Compatibilité avec le graphe existant

Puisque `Node::channel()` retourne désormais ChannelID, une surcharge
`DAG::connect(ChannelID, ChannelID)` décode les deux identifiants et délègue aux
validations existantes. Les codes de port inconnus sont conservés et refusés
par `InvalidDirection`, sans normalisation. La surcharge historique prenant
des Channel est conservée ; aucun adaptateur mixte ni refonte du stockage des
arêtes n’est ajouté.

Ce paragraphe décrit l’adaptateur livré en S01-07. Le stockage est ensuite
migré vers `Connection{ChannelID from, ChannelID to}` dans
[S02-02](../sprint-02/S02-02.md), avec adaptation des Channel historiques après
vérification de leurs champs larges.

[S02-03](../sprint-02/S02-03.md) harmonise ensuite les deux surcharges vers
`connect(destination, source)` et distingue les codes de ports invalides des
directions interdites. Ce contrat remplace la convention d’adaptation historique.

Les tests négatifs de ports construisent leurs identifiants malformés
directement au lieu d’appeler `Node::channel()`/`encode()` hors précondition.
Les directions, cycles, doublons, occupations et canaux hors layout gardent
leurs tests de non-régression.

À la livraison de S01-07, le compteur historique 64 bits de `DAG::add()` et son
cas d’épuisement du domaine 32 bits restent une limite connue de S01-01 ; cette fiche
ne présente pas la fabrique du DAG comme corrigée sur ce point. Le tri
topologique et `ExecutionPlan::exec()` restent inchangés. Aucun travail de
marquage/routage backend ou des sprints de publication n’est revendiqué.

## Validation exécutée

Compilation C++26 complète réussie avec Clang 19.1.7/libc++19, CMake 4.3.4 et
Ninja. Lors de la livraison de S01-07, **87 tests CTest passent**, soit les 69 tests
précédents et **18 nouveaux tests** (9 interface/traitement, 7 emprunts/durée de
vie, 2 instrumentation RT),
sans test ignoré ou désactivé. `git diff --check` passe.

- Assertions statiques des signatures exactes, abstraction, destructeur virtuel,
  classe non final, process pure et latence non pure, absence de prepare et
  suppression des copies/déplacements de Node et de son propriétaire DAG.
- Latence zéro par défaut, override 128 et UINT32_MAX par dispatch virtuel ;
  masquage dans un dérivé pour vérifier le dispatch non virtuel des accesseurs.
- Identités 32 bits et ChannelID aux bornes, valeur numérique de référence,
  configuration propriétaire et vues matérielles renouvelées entre callbacks.
- Suppression refusée sans mutation tant qu’un plan emprunte le Node ; libération
  indépendante de plusieurs plans, copies/déplacements et auto-affectations.
- Traitement sur un thread de travail, puis retraite des plans et destruction
  polymorphe sur le thread propriétaire après join, sans accès concurrent non
  synchronisé aux compteurs du test.
- Cible `mka-node-rt-tests` séparée avec interception de new/delete C++ : témoin
  positif d’allocation/libération, puis **zéro opération de tas C++ mesurée sur
  64 callbacks** avec traitement effectif et résultats audio vérifiés.

L’interception est locale à cet exécutable de test, jamais liée à la
bibliothèque. Elle ne prétend pas intercepter tous les appels C malloc/libres,
les locks ou I/O d’un effet utilisateur arbitraire. Le processeur de test
n’utilise aucun de ces appels ; le test mesure son chemin réel via Node.
