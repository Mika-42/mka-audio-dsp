## API publique

Le module `mka.audio.dsp.channel` réexporte les alias de
`mka.audio.dsp.types` et fournit dans `mka::audio::dsp` :

```cpp
constexpr ChannelID encode(NodeID node, PortType port, ChannelIndex index) noexcept;
constexpr NodeID decodeNode(ChannelID id) noexcept;
constexpr PortType decodePort(ChannelID id) noexcept;
constexpr ChannelIndex decodeChannel(ChannelID id) noexcept;
```

Les quatre fonctions sont `[[nodiscard]]`, pures, sans allocation, exception,
I/O ni accès partagé ou backend. Elles utilisent exclusivement des conversions
non signées, des décalages et des masques explicites sur 64 bits. Elles peuvent
être évaluées à la compilation ou exécutées sur un thread sans synchronisation ;
les valeurs externes doivent être validées en contrôle avant leur usage audio.

## Format numérique

| Bits (inclusifs) | Largeur | Champ |
|---|---|---|
| 63..32 | 32 | NodeID |
| 31..16 | 16 | PortType, codes In=0 / Out=1 / Aux=2 |
| 15..0 | 16 | ChannelIndex, de 0 à 65535 |

Exemple de référence :

```cpp
encode(0x12345678, PortType::Out, 0xABCD) == 0x123456780001ABCDULL
```

Les champs ne se chevauchent pas. Le résultat est une identité **logique**
numérique, jamais un pointeur ou un numéro de voie matérielle. Il ne possède
aucun buffer et ne garantit pas la présence ou la durée de vie d’un nœud.
Toutes les valeurs de NodeID peuvent être représentées, y compris 0 et
UINT32_MAX : encoder 0 ne fait pas de 0 une identité valide de nœud vivant.

Le format de bits de l’entier est indépendant de l’endianness de la machine.
Cela ne fixe pas un ordre d’octets pour un fichier ou un protocole réseau :
copier la représentation mémoire brute d’un entier n’est pas une sérialisation
portable. Aucune API de sérialisation d’octets n’est ajoutée par cette fiche.

## Préconditions et ports inconnus

La variante demandée `encode` exige **`isValidPort(port)`** en précondition,
comme l’autorise la fiche. Elle ne valide pas dynamiquement cette condition et
ne renvoie pas un `expected`. Les appels sur des ports inconnus sont hors
contrat. Un entier large destiné à l’indice doit être contrôlé par
`toChannelIndex` avant toute conversion réductrice, conformément à S01-01.

Les décodeurs acceptent tout ChannelID, y compris un entier arbitraire ou
UINT64_MAX. `decodePort` restitue exactement le champ 16 bits : il ne transforme
jamais un code inconnu en In/Out/Aux. L’appelant doit le valider séparément :

```cpp
import mka.audio.dsp.channel;
using namespace mka::audio::dsp;

constexpr ChannelID external = 0x12345678FFFFABCDULL;
constexpr auto port = decodePort(external);
static_assert(!isValidPort(port)); // 65535 est conservé, pas normalisé
```

L’encodage ne recherche pas le nœud, ne valide pas le layout et n’affecte pas
les arêtes du DAG. La classe historique `Channel` et les signatures de Node/DAG
ne sont pas migrées : ces intégrations appartiennent aux fiches suivantes.

## Validation exécutée

Compilation C++26 complète réussie avec Clang 19.1.7/libc++19, CMake 4.3.4 et
Ninja. Lors de la livraison de S01-03, **31 tests CTest passent**, soit les 23 tests des fiches précédentes et
**8 nouveaux tests** de S01-03, sans test ignoré ou désactivé.

- Assertions statiques des signatures et retours exacts, `noexcept`, résultats
  `constexpr`, valeurs minimales/maximales et port inconnu.
- Valeurs numériques de référence indépendantes, dont
  `0x123456780001ABCD`, et les 27 combinaisons des bornes NodeID 0/1/max,
  des trois ports officiels et des indices 0/1/65535.
- Les 65 536 indices pour chaque port officiel, avec préfixes numériques
  attendus explicites et vérification des autres champs.
- Isolation de chacun des 64 bits lors du décodage ; préservation de chaque
  bit du NodeID à l’encodage, y compris le bit 63 du résultat.
- Absence de collision sur 120 tuples distincts variant les trois champs.
- Les 65 533 codes de port inconnus sont tous préservés au décodage et refusés
  par `isValidPort`, `isInputPort` et `isOutputPort`, sans altérer les autres
  champs. Ces données malformées sont construites directement, sans appel à
  `encode` hors de sa précondition.
- Identifiants 64 bits arbitraires, notamment UINT64_MAX et des motifs de bits,
  comparés à un oracle par divisions/restes indépendant des décalages/masques ;
  recomposition exacte sans perte de bits.

Le nouveau fichier de test importe uniquement `mka.audio.dsp.channel` et
vérifie ainsi aussi la disponibilité publique des alias réexportés. La revue de
code n’a trouvé aucun problème bloquant. `git diff --check` passe.

  -DFETCHCONTENT_SOURCE_DIR_GOOGLETEST=/workspace/.mka-build/native-tests/_deps/googletest-src

ctest --test-dir /workspace/.mka-build/s01-03 --output-on-failure --no-tests=error

revendique aucun comportement de traitement audio.
