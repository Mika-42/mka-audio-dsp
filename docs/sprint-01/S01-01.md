## API livrée

Le module public `mka.audio.dsp.types` expose dans `mka::audio::dsp` :

| Alias | Type exact | Unité / signification |
|---|---|---|
| `NodeID` | `std::uint32_t` | Identité numérique d’un nœud logique |
| `ChannelID` | `std::uint64_t` | Identité numérique d’un canal logique, jamais une adresse |
| `ChannelIndex` | `std::uint16_t` | Numéro de canal logique, de 0 à 65535 inclus |
| `FrameCount` | `std::uint32_t` | Nombre de frames, donc d’échantillons par canal |

Ces alias sont des entiers non signés, sans allocation, propriété de mémoire,
constructeur dédié ou comportement polymorphe. Leur lecture ne dépend d’aucun
état partagé. `FrameCount` formalise le contrat cible ; la migration du champ
historique `ProcessContext::frames` (`std::size_t`) appartient à S01-06.
La capacité backend doit être vérifiée avant une conversion vers `FrameCount`.
Zéro frame interdit toute lecture/écriture d’échantillon.

```cpp
import mka.audio.dsp.types;

// toChannelIndex est un template contraint aux types entiers standard.
// Résultat : std::expected<ChannelIndex, ErrorType>.
const auto valid = mka::audio::dsp::toChannelIndex(65535); // succès exact
const auto invalid = mka::audio::dsp::toChannelIndex(65536); // erreur de plage
```

`toChannelIndex(Integer)` est `[[nodiscard]] constexpr noexcept`. Une valeur
négative ou supérieure à 65535 retourne
`std::unexpected(ErrorType::InvalidChannelIndex)` **avant** le cast : aucun
masquage ni rebouclage à 0 ou 1. Les entiers courts et les types caractères sont
acceptés selon leur valeur numérique ; `false` et `true` donnent 0 et 1.
Les flottants, enums et pointeurs sont rejetés à la compilation.

Cette opération pure n’alloue, ne verrouille, ne loggue et ne lance aucune
exception. Elle sert à valider les données en contrôle avant utilisation par
le thread audio. Aucun traitement audio n’est ajouté par cette fiche.

## Contrat NodeID et limite d’intégration à examiner

- `invalidNodeID == 0` est réservé à une identité invalide/non attribuée.
- Les identités de nœuds vivants occupent `[1, UINT32_MAX]` ; `maxNodeID`
  donne la dernière valeur représentable.
- Un allocateur doit signaler l’épuisement **avant** tout cast réducteur ou
  incrément débordant. Il ne doit pas reboucler à zéro.
- Un ID ne doit jamais être réutilisé tant qu’un plan peut encore référencer
  l’ancien nœud. Cette exigence porte sur la durée des références, pas sur la
  seule présence du nœud dans le graphe éditable.

**À la livraison de S01-01, ce contrat n’était pas encore garanti par
l’allocateur historique.** `DAG::add()` incrémentait un compteur 64 bits transmis à un
constructeur de Node prenant 32 bits : après `UINT32_MAX`, il peut tronquer
l’identité. Cette fiche introduit les types et conversions, sans changer les
API de Node ou de DAG. Le critère d’intégration « aucun NodeID réutilisé » ne
doit donc pas être présenté comme vérifié dynamiquement. La validation de cette
fiche n’ajoute pas cette garantie à l’allocateur ; elle reste un travail
d’intégration du DAG distinct du contrat de types accepté.

Cette limite d’intégration est traitée par [S02-01](../sprint-02/S02-01.md) :
contrôle de l’épuisement avant conversion et identité validée seulement après
insertion réussie, sans réutilisation pendant la durée de vie du DAG.

## Tests exécutés

La fiche dispose de **7 tests GoogleTest** dans `mka-audio-dsp-tests`, tous passés
en Debug avec Clang 19.1.7/libc++19, CMake 4.3.4 et C++26.

| Cas | Vérification |
|---|---|
| Types exacts, largeur et propriétés | Assertions statiques sur les alias, tailles 4/8/2/4 octets, bits 32/64/16/32, entiers non signés triviaux |
| `constexpr` / `noexcept` / retour | Succès et erreurs évalués à la compilation ; type de retour exact |
| Bornes nominales | 0, 1, 65534, 65535 conservés exactement |
| Domaine complet valide | Les 65536 indices sont vérifiés depuis uint32_t et uint16_t |
| Dépassements | 65536, 65537, 131071, UINT32_MAX, UINT32_MAX+1, UINT64_MAX sont rejetés |
| Bits hauts | Chaque bit de position 16 à 63 est rejeté avec les bits bas à 0, 1 et 65535 |
| Signés | Négatifs, INT64_MIN, INT64_MAX ; 0 et 65535 restent valides |
| Types sources | Tous les types entiers standard, y compris caractères et booléens ; flottants/enums/pointeurs exclus à la compilation |

La bibliothèque complète et l’exécutable existant compilent et se lient.
L’exécutable vide termine avec le code 0 ; cela ne valide aucun traitement DSP.
Aucune suite préexistante de DAG n’était présente dans le checkout.

## Corrections nécessaires pour exécuter ces tests

Ces corrections de compilation ne livrent pas une autre fiche :

1. Déclarer `process_context.cppm` dans le `FILE_SET CXX_MODULES` de CMake.
2. Déplacer l’inclusion de `<cstdint>` dans le fragment global de `channel.cppm`.
3. Importer le véritable module `process_context` dans `execution_plan.cppm`
   au lieu de redéclarer son type dans un autre module.
4. Remplacer la liste CMake des quatre tests absents par le nouveau
   `test/test_types.cpp`. Aucun fichier de test existant n’a été supprimé.

## Reproduire dans l’environnement préparé

```bash
source /workspace/.mka-setup/activate.sh
cmake -S /workspace/mka-audio-dsp -B /workspace/.mka-build/s01-01 -G Ninja \
  -DCMAKE_TOOLCHAIN_FILE=/workspace/.mka-setup/toolchain.cmake \
  -DCMAKE_BUILD_TYPE=Debug -DCMAKE_EXPORT_COMPILE_COMMANDS=ON \
  -DFETCHCONTENT_SOURCE_DIR_GOOGLETEST=/workspace/.mka-build/native-tests/_deps/googletest-src
cmake --build /workspace/.mka-build/s01-01 --parallel 4
ctest --test-dir /workspace/.mka-build/s01-01 --output-on-failure --no-tests=error
```

Le toolchain local sélectionne Clang/libc++ et le cache GoogleTest évite un
téléchargement supplémentaire. Ces commandes n’utilisent pas l’override CMake
provisoire créé pendant l’onboarding.
