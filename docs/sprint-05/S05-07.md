# S05-07 — Intégration du pool dans le compilateur

La préparation construit d'abord l'ordre final Node + retards explicites,
décrit toutes les productions/lectures, calcule liveness et slots, vérifie la
preuve puis le budget complet. Elle prépare exactement `peakSlots`, le silence
distinct et les historiques persistants. Les SignalID sont ensuite traduits en
BufferId validés, et les pointeurs sont liés après la dernière allocation.

`BackendConfig::connectionDelays` emprunte sur contrôle les retards par arête
fournis par une analyse PDC externe. Les retards sont insérés avant leur lecteur,
avec production distincte même pour D=0 ; D>0 utilise un anneau persistant mono.
Cette fiche ne fait pas l'analyse automatique des latences (sprints 8/9).
Les arêtes hors layout n'accèdent à aucun slot non préparé et restent silencieuses.
Le span de configuration n'est jamais retenu après préparation.

Les In/Aux reliés lisent leurs producteurs, les autres partagent le silence,
les outputs logiques écrivent dans les slots. Les sources reçoivent toujours
toutes les entrées physiques ; backendOutputs est rebindé séparément pour les
Nodes marqués output, y compris avec successeurs. Le callback parcourt les
opérations déjà liées sans lookup de slot, allocation, freelist ou mutex.

L'état audio est construit directement dans une allocation heap stable et
échangé seulement après validation complète. Cet AudioState et le BufferPool
ne sont jamais déplacés après binding. Le wrapper ExecutionPlan peut être
déplacé sur contrôle après quiescence : seul son unique_ptr est transféré,
les buffers et les spans ne bougent pas. Une copie de contrôle possède son
pool et ses historiques, avec rebinding de tous les descripteurs.

`memoryBudgetBytes` couvre maintenant les payloads retenus du plan complet
(capacités réellement réservées, sizeof des objets/tableaux, PCM, silence,
historiques et réserve d'alignement). Les temporaires de contrôle et le coût
interne de malloc restent exclus. `preparedMemoryUsage`, `signalLifetimes`,
`signalSlots` et `bufferSlotCount` exposent des diagnostics const sur contrôle.
Le plafond `maxBufferSlots` et `SlotStrategy::Unique` sont configurables.
Les allocations refusées de l'API de compilation audio retournent PrepareFailed ;
la compilation structurelle historique conserve sa catégorie de compatibilité.

Tests : chaîne stéréo 31 Nodes (4 slots au lieu de 62), multi-source/fan-out/Aux,
output avec successeur, retards, copies/moves de contrôle et adresses stables.
Budget exact accepté, un octet de moins et capacité insuffisante refusés sans
altérer A. Injection à chaque allocation de préparation avec retard ; callbacks
instrumentés sans new/delete/mutex. Le corpus indépendant détaillé suit en S05-08.
