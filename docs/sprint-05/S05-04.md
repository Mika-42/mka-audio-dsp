# S05-04 — Affectation statique et recyclage

`assignBufferSlots` parcourt les opérations finales : réserve tous les slots
produits avant l'opération, puis libère les intervalles expirés après celle-ci.
Les intervalles sont inclusifs ; même la dernière entrée d'un Node reste
distincte de sa sortie. Le résultat contient `slotOf`, `peakSlots` (capacité
physique) et `peakLiveSlots`. Les buckets de début/fin et la freelist sont
temporaires sur contrôle, sans acquire/release dans le callback.

`SlotStrategy::Unique` réserve un slot par production pour les rendus témoins.
Le plafond de slots est vérifié avant incrément de l'ID uint32_t. Les intervalles
invalides sont refusés, et les exceptions d'allocation deviennent CompileError.

Tests : chaîne de 100 productions avec seulement deux slots, disjonction
exhaustive des intervalles, diamant avec lecteur tardif et DelayTask, comparaison
des valeurs calculées avec un stockage unique, et refus de capacité. Les tests
de rendu multi-callbacks et de véritables historiques seront ajoutés lors de
l'intégration S05-07 puis étendus par l'oracle S05-08.
