## Procédures, résultats et exclusions

Les procédures automatiques reproduisent un backend fake, sans carte son physique. Les scripts `tools/check-sanitizers.sh`, `tools/run-benchmark.py` et `tools/check-requirements.py` enregistrent/vérifient les résultats. Aucune procédure sur driver matériel ni plugin binaire tiers n'a été exécutée dans le cloud ; stop/join réel est une précondition de l'adaptateur, couverte par les tests de backend simulé, pas une observation de matériel utilisateur.

G-10/SW-06 distinguent retrait du désiré et destruction : remove peut réussir pendant A/B, l'owner reste dans retiredNodes jusqu'au dernier emprunt. P-09 aligne les jonctions logiques connues ; aucune synchronisation par voie physique arbitrairement écrite n'est promise. P-12 démontre les conséquences d'une déclaration fausse, sans détection automatique ni correction.

Hors périmètre, sans coche d'implémentation : tails audibles après retrait ; parallélisme DSP ; mapping hardware par ChannelID ; exclusivité des writers ; migration/préchauffage d'historiques et crossfade ; MIDI/automation ; mesure/compensation de latence hardware inconnue. Les anciens noms DoubleBuffer et ctx.outputs matériel dans les archives sont remplacés respectivement par PlanSwitcher et ctx.backendOutputs. Les signatures actives sont ExecutionPlan::exec, ProcessContext::backendOutputs et DelayLine::prepare(uint64_t).
